# SCADA 機櫃（SoW V6 附錄 D）— 逐台輸出含設備資訊的 RFA

## 檔案
| 檔案 | 用途 |
|---|---|
| `SCADA_Racks_SoW_V6.csv` | 36 台機櫃資料＋定位設定，可用 Excel 修改 |
| `SCADA_Racks_SoW_V6.dyn` | Dynamo 圖檔（Revit 2025 / Dynamo 3.3，CPython3） |
| `scada_racks.py` | .dyn 內嵌的同一份程式，.dyn 打不開時可貼到 Python Script 節點 |
| `族群\SCADA_機櫃_<編號>.rfa` | 執行時產生 36 個電氣設備族群：一台一檔，各自帶完整設備資料 |
| `建築模型房間快取.json` | 執行後自動產生：各建築模型的房間座標與共用座標，模型檔沒變就不重開 |

## 使用步驟
1. Revit 2025 開一個空白專案（只當執行環境，機櫃不會建在這裡）。
2. 管理 → Dynamo → 開啟 `SCADA_Racks_SoW_V6.dyn`，按「執行」。
3. 預設「匯出 NWC」「存每站 RVT」均為 False，只產生 36 個 RFA，不開啟建築模型，也不建立逐站專案。
4. Watch 應顯示「設備族群 36 個（每台 16 欄預設資料已驗證）」、36 個 RFA 路徑與「僅輸出 RFA 完成」。
5. 在 Revit 載入需要的 RFA 並放置；每個族群已填入該台的編號、站點、房間、尺寸、UPS、規範項次與來源文件。

如需額外輸出整站 RVT／NWC，再把對應開關設為 True。此模式會開啟建築模型讀取房間並套用原定位邏輯；模型沒變時使用快取。Navisworks 開啟整合模型 NWD，再附加對應 NWC。

## 定位怎麼運作（CSV 的定位欄位）
| 欄位 | 說明 |
|---|---|
| `建築模型` | 該站建築 RVT 路徑（相對於 CSV 所在資料夾）。空白 = 放在原點 |
| `房間關鍵字` | 以 `|` 分隔，依順序比對房間名稱或編號，先比到的優先，例如 `SCADA|通訊號誌|通訊` |
| `X偏移mm`、`Y偏移mm` | 在自動位置上再平移（模型內部座標方向），手動微調用 |
| `旋轉度` | 以機櫃中心逆時針旋轉的角度 |

- 機櫃中心放在房間的「位置點」，底部在房間樓層高程；同一房間多台會沿 X 方向並排。
- 每站 RVT 會套用該建築模型的共用座標，NWC 以共用座標匯出。
- **重跑時保留**：腳本只讀 CSV、不回寫，你填的偏移、旋轉、關鍵字都會保留。
- 實際配對到哪個房間寫在參數 `SCADA_定位來源`（Navisworks「自訂」頁籤可看），比錯就改 `房間關鍵字` 重跑。

元素屬性另有標記（＝編號）、備註。

## 機櫃攜帶的資訊

逐台 RFA 版程式已更新，需重新開啟 `.dyn` 並執行才會產生 36 個設備族群。重跑前請關閉 Revit 內開啟的同名輸出 RFA；若啟用 RVT 輸出，也須關閉對應 RVT，避免檔案被佔用。請從空白專案執行。先前兩個按尺寸命名的 RFA 保留在資料夾中，不屬於這次 36 台設備交付清單。

2026-10-28 逐台 RFA 版已完成 Revit／Dynamo 實跑：使用者提供完整 Watch 結果「設備族群 36 個（每台 16 欄預設資料已驗證）」及「僅輸出 RFA 完成」，無失敗訊息。已核對磁碟上 36 個設備 RFA 與 CSV 編號一一對應、全部非空，沒有缺檔。另案載入後的屬性與尺寸抽查仍待確認。

- **族群本身**：一台一個檔案，15 個 CSV 資料欄位與 1 個定位來源欄位均為族群內建的共用實例參數；各設備的實際值直接預填在 RFA 中，提交交易後比對正確才存檔。
- **手動放置**：載入後已帶該台設備的編號、期別、站點、建物、房間、尺寸、UPS 配置與附錄項次，不需重新輸入。RFA 幾何以族群內部原點建立，載入專案後需定位；`SCADA_定位來源` 標為「獨立設備族群（載入專案後定位）」。重複放置同一 RFA 會重複設備編號，不能當作另一台設備使用。
- **Dynamo 放置**：依每列 CSV 寫入編號、期別、站點、建物、房間、機櫃類型、寬深高、尺寸、附錄 D／F 項次、UPS 配置、來源文件及備註，另寫入實際定位來源。CSV 原本空白的備註仍保留空白。
- **驗證**：以共用參數 GUID 寫入，並在交易提交後逐台逐欄讀回比對；Watch 必須顯示「資料驗證 2 台×16 欄通過」後才會匯出該群組。這是輸出前的 Revit 資料檢查，Navisworks 匯出後的屬性仍須抽查。

在 Revit 選取機櫃後，向下捲動「性質」至「資料」群組即可查看該設備的 `SCADA_` 資料。

## 執行前檢查 CSV（不需要 Revit）
在工具資料夾執行，只讀 CSV 與 `建築模型房間快取.json`，不寫任何檔案：
```
python validate_racks.py
```
列出 [錯誤]（缺欄、缺編號、編號重複、尺寸或偏移不是有限數字、同群組建築模型不一致等）與 [警告]（備註「待確認」、房間關鍵字在快取中沒命中、找不到建築模型）。有錯誤時 exit code = 1。

單元測試：
```
python -m unittest discover -s tests -v
```

## 產生設備清冊與報表（不需要 Revit）

```
python report_racks.py
```

輸出 `報表\SCADA_設備清冊.xlsx` 與 `報表\SCADA_儀表板.html`，包含設備清冊、各站統計、檢查結果及依房間快取推算的預計房間。預計房間不是本次 Revit 實跑結果，實際定位以 `SCADA_定位來源` 為準。

Excel 輸出需要環境中已有 `openpyxl`，程式不會自動安裝；缺少時仍產生 HTML，並回傳失敗狀態。可用 `--out <資料夾>` 指定輸出位置。CSV 有錯誤時預設停止輸出；`--force` 可產生標示「資料有錯誤」的報表，但退出碼仍為 1。覆寫單一檔案失敗時保留該檔舊版。

## 逐台 RFA 版驗收（實跑與檔案核對完成，待另案載入抽查）

主要交付物為 36 個依設備編號命名、帶各自完整資料的 RFA；不能以兩個尺寸共用族群或整站 RVT 代替。

目前第 1、2 項已完成；第 3、4 項另案載入抽查及第 6 項設定復原確認尚未回報。第 5 項為選用輸出，不影響本次 RFA 交付。

1. 用空白專案執行 `.dyn`，保存 Watch 完整輸出；全域及各群組均不得出現「失敗」。本程式會覆寫同名 RFA、RVT 與 NWC，需保留的舊成果請先自行備份。
2. 確認 `族群\` 產生 36 個 `SCADA_機櫃_<編號>.rfa`，例如 `SCADA_機櫃_SB10-COMS-RTU-01.rfa`，編號與 CSV 一一對應。
3. 將 SB10 的 RTU 與 PLC RFA 載入另一個空白專案、各放一台；確認為電氣設備族群，類型與尺寸對應 CSV。
4. 選取兩台機櫃，核對 `SCADA_編號`、站點、房間、UPS 配置及來源文件；應帶實際值，非共用範本的「待填」。CSV 原本空白的備註仍可空白。
5. 如另外啟用 RVT／NWC 輸出，再確認 18 組輸出與逐站資料驗證；在 Navisworks 抽查 SB10 的位置、高程與機櫃屬性。
6. 確認 Revit 原本的共用參數檔設定已復原；若失敗，保留完整「失敗:」訊息，避免把舊輸出當成本次結果。

以上通過後，才能將族群版標記為驗收完成。沒有建築模型的群組仍按 CSV 設定放在原點。

## 注意
- 機櫃為電氣設備**族群**（固定尺寸方塊，由 `公制電氣設備.rft` 產生），每台設備一個族群，以編號命名；尺寸不是可拉伸參數，改尺寸請改 CSV 重跑。
- 族群可直接載入其他專案使用（`族群\` 資料夾）。
- 編號（如 `SB10-COMS-RTU-01`）是暫訂命名，不是業主正式設備編碼。
- PLC 機櫃：附錄 D 彙總表寫 1 座、明細 17 座，CSV 依明細建 17 台，`SCADA_備註` 標「數量待確認」。
- 預設房間關鍵字：COMS RTU 機櫃 `SCADA|通訊號誌|通訊`（五站都配到「通訊/SCADA設備室」）；
  TSS PLC 機櫃 `牽引|TSS`（SB10 F351、SB11 F115 TSS、SB14 F334、SB15 F314「牽引動力配電室」，
  SB12 F446「牽引動力變電室」）。目前 5 站 10 台全部配到房間，執行後可在 `SCADA_定位來源` 確認。
- 對齊前提：各站整合模型 NWD 的 NWC 是以共用座標匯出；若整合模型用的是內部原點，位置會差一個共用座標的位移。
- 共用參數檔在 `NWC\SCADA_SoW_V6_SharedParameters.txt`；執行後會還原你原本設定的共用參數檔。
